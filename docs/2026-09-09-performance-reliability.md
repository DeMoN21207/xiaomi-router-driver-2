# Производительность и устойчивость VPN Manager — 9 сентября 2026

Проверка локального приложения и исправления в ветке `codex/router-performance-reliability`, база `31f92b9`. Настройки действующего роутера не получены: SSH, HTTP и ICMP к `192.168.31.1` возвращают ошибку доступности из текущего окружения. Изменения авторизации не входят в работу.

## Исправлено

- Применение маршрутов сохраняет только результат операции вместо перезаписи всей конфигурации старым снимком. Изменения настроек, сделанные после получения снимка, сохраняются. Ошибки записи результата возвращаются вызывающему коду; ответ об успехе больше не скрывает такую ошибку. Отдельно проверены успешное и неуспешное применение.
- Дочерние записи правил и политик читаются четырьмя групповыми SQL-запросами вместо отдельных запросов для каждого владельца. Сохранены принадлежность записей, порядок правил, доменов, целей и расписаний. Для измеренного набора число запросов чтения конфигурации уменьшилось с 296 до 10.
- Нормализация доменов использует уже определённый тип записи при удалении покрываемых поддоменов. Обычные имена без порта не проходят лишний разбор `host:port` и IP с выделением объектов ошибок. Сохранена обработка IPv4, CIDR, URL, локальных имён и импортируемых списков. Отдельные тесты защищают сочетания IPv4 URL с числовым доменом и именем вида `host.192.168.1.1`.
- Все девять хранилищ отмечают инициализацию завершённой только после успеха: конфигурация, домены, события, OpenVPN, подписки, история трафика, трафик доменов, доступность доменов, трафик сайтов. Временная невозможность записи при первом обращении больше не закрепляет ошибку до перезапуска процесса.
- Перенос старого манифеста подписок в SQLite выполняется одной транзакцией. Ошибка на второй записи откатывает первую; повторная попытка переносит весь набор, сохраняя активные файлы конфигурации.
- Расчёт CPU исключает повторный учёт `guest`/`guest_nice`, учитывает `iowait` вместе с простоем и обрабатывает уменьшающиеся/несогласованные счётчики без переполнения. Чтение и обновление общей базы измерения защищены от одновременных HTTP-запросов. Особенности счётчиков описаны в [документации ядра Linux](https://docs.kernel.org/admin-guide/cpu-load.html) и [описании /proc](https://www.kernel.org/doc/html/latest/filesystems/proc.html).
- OpenVPN больше не привязан к времени жизни команды применения настроек. Раньше `defer cancel()` после успешного применения завершал VPN, запущенный через `exec.CommandContext`. Реальный дочерний процесс в регрессионном тесте завершался с `signal: killed`; после исправления переживает завершение команды и останавливается явной очисткой. Семантика отмены описана в [документации Go](https://pkg.go.dev/os/exec#CommandContext).
- Ожидание появления VPN-интерфейса учитывает отмену и тайм-аут применения. При ошибке запуска собственный процесс завершается даже при недоступной БД; при первой ошибке сохранения он также корректно освобождается через `Wait`. Отдельный тест закрывает SQLite во время запуска и проверяет отсутствие оставшегося процесса.
- Снимки OpenVPN и sing-box освобождают блокировку менеджера сразу после чтения независимых записей из БД. Проверка интерфейсов, процессов и ping OpenVPN больше не удерживает блокировку, нужную для применения, очистки и обработки завершения VPN. Проверка доступности сохранена; время самого ping не сокращалось.
- Архив обновления передаётся из multipart-запроса сразу в рабочий каталог на диске, без предварительного буфера до 128 МиБ и второго временного файла multipart. Занятый или недоступный установщик отклоняет запрос после заголовков, не считывая весь архив.
- Временные архивы и распакованные файлы удаляются после успешной установки, некорректного архива и обрыва загрузки. Резервная копия установленной версии сохраняется отдельно. Отмена запроса до начала замены файлов больше не приводит к установке; после начала замены операция доводится до своего результата.

## Измерения

Apple M5 Pro, macOS ARM64, локальный Go из `.tools/go`. Один поставщик, 200 правил по 20 доменов, 30 политик приоритетов. Медианы трёх запусков `BenchmarkLoadLargeConfig` без детектора гонок:

| Показатель одного чтения | До | После |
| --- | ---: | ---: |
| Время | 10,198 мс | 4,423 мс |
| Выделено памяти | 5 557 802 байта | 2 252 479 байт |
| Число выделений памяти | 122 119 | 55 359 |

Чтение быстрее в 2,31 раза; объём выделений меньше на 59,5%. Это затраты операции чтения конфигурации, а не RSS процесса, пропускная способность VPN или измерение на роутере.

Воспроизведение из корня проекта:

```sh
.tools/go/bin/go test ./internal/config -run '^$' -bench BenchmarkLoadLargeConfig -benchmem -count=3
.tools/go/bin/go test ./internal/domains -run '^$' -bench BenchmarkNormalizeRoutingEntry -benchmem
```

Дополнительный тест загрузки: multipart-файл 16 МиБ, полностью принятый установщиком и затем отклонённый как некорректный gzip. Медианы трёх одиночных запусков `BenchmarkUpdateUpload` на том же Mac:

| Показатель загрузки | До | После |
| --- | ---: | ---: |
| Выделено памяти | 67 182 864 байта | 61 088 байт |
| Время | 10,782 мс | 17,076 мс |

Это снижение выделений памяти примерно с 64 МиБ до 60 КиБ, а не измерение пикового RSS или скорости VPN. Новый путь включает потоковую запись и удаление временного каталога; выигрыша по времени в этом локальном тесте нет. Приоритет изменения — избежать большого буфера в ограниченной памяти роутера и накопления файлов на диске.

```sh
.tools/go/bin/go test ./internal/api -run '^$' -bench '^BenchmarkUpdateUpload$' -benchmem -benchtime=1x -count=3
```
