# Усиление устойчивости VPN Manager — 2026-09-10

Обновление приложения теперь копируется во временный каталог на том же разделе и устанавливается через журналируемую транзакцию. При остановке питания или ошибке запуска сервис восстанавливает предыдущий runtime, не затрагивая `data/`. Перезапуск после обновления выполняется через `exec` только после остановки HTTP, фоновых задач, DNS-прокси и SQLite.

Watchdog проверяет PID и `/proc/<pid>/exe`, пропускает активное обновление и использует неограниченный procd respawn. Скрипт развёртывания ставит отдельную блокировку и снимает её после успешного healthcheck.

WAN проверяется по нескольким адресам через интерфейс default route. Локальное восстановление пропавшего VPN runtime выполняется даже при недоступности публичного ping; переключение провайдера по-прежнему требует подтверждённого WAN.

SQLite использует `synchronous=FULL`, 15-секундный busy timeout, `quick_check`, WAL checkpoint и атомарную резервную копию через `VACUUM INTO`. Повреждённая основная база сохраняется, после чего используется последняя проверенная копия.

Ручное применение правил стало фоновой операцией с пятиминутным пределом и опросом статуса из интерфейса. При ошибке откат касается только изменённого правила и не перезаписывает более свежую пользовательскую правку.

Изменяющие API-запросы можно защитить Bearer-токеном через `VPN_MANAGER_API_TOKEN` или файл `data/api-token`. Тело запроса ограничено 128 МиБ. DNS-прокси ограничивает параллелизм, использует прямой Do53 fallback и circuit breaker; его состояние видно в `/api/status`.

Для новой установки включены сервис и автовосстановление. Минимальный период обновления панели — пять секунд, обычные быстрые GET не пишутся в лог, а `doctor` проверяет целостность базы, backup, место, watchdog, update journal и PID владельца процесса.
